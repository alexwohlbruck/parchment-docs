Parchment serves the same tools that power **Ask** over the [Model Context Protocol](https://modelcontextprotocol.io) (MCP). Connect an MCP client, and its model can search your server's places and work out how to reach them: your assistant does the reasoning, Parchment supplies real places, timetables and conditions.

Unlike Ask, MCP needs no OpenRouter key. The client brings its own model.

---

## Endpoint

```
https://<your server>/mcp
```

A stateless [Streamable HTTP](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports#streamable-http) server: one JSON-RPC message per `POST`, answered with JSON. There is no event stream and no session, so `GET` and `DELETE` answer `405`.

---

## Access

Every request needs a signed-in user with the `premium:ask` permission (the Premium role) and Ask turned on in their settings. A request without a valid session gets `401`; a user without the permission gets `403`. Both carry a JSON-RPC error body.

Authenticate with a session token in the `Authorization` header:

```
Authorization: Bearer <session token>
```

### Getting a token

Parchment has no personal access tokens yet. A token is an ordinary sign-in session, so the cleanest way to get one is to sign in once from the command line. That makes a separate session for the assistant, which you can revoke without signing out anywhere else.

```bash
# 1. Email yourself a sign-in code
curl -X POST https://<your server>/auth/verify \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com"}'

# 2. Exchange the code for a session token
curl -X POST https://<your server>/auth/sessions \
  -H 'Content-Type: application/json' \
  -d '{"method":"otp","email":"you@example.com","token":"<code from the email>"}'
```

The response's `token` field is the session token.

- It expires after 30 days without use. Each use within that time extends it.
- It shows up under **Settings → Account → Sessions**, where you can revoke it.
- It is a full sign-in for your account, not a token limited to search. Keep it as private as a password.

<Callout type="warn">
Hosted connectors in claude.ai and ChatGPT expect to sign in with OAuth, which Parchment does not offer yet. Use a client that lets you set a request header, like Claude Code, or a bridge such as `mcp-remote`.
</Callout>

## Connecting a client

### Claude Code

```bash
claude mcp add --transport http parchment https://<your server>/mcp \
  --header "Authorization: Bearer <session token>"
```

### Claude Desktop

Claude Desktop's config file cannot set headers on a remote server, so bridge it with [`mcp-remote`](https://www.npmjs.com/package/mcp-remote). In `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "parchment": {
      "command": "npx",
      "args": [
        "mcp-remote",
        "https://<your server>/mcp",
        "--header",
        "Authorization:${PARCHMENT_AUTH}"
      ],
      "env": {
        "PARCHMENT_AUTH": "Bearer <session token>"
      }
    }
  }
}
```

The header goes through an environment variable because some platforms split arguments that contain a space.

Any other client that speaks Streamable HTTP and can send a header works the same way.

## Tools

| Tool | What it does | Returns |
|---|---|---|
| `find_places` | Search by name or free text ("ramen", "Blue Bottle") around `near` | Places ranked by relevance and distance |
| `find_categories` | Look up category ids for a kind of place ("bakery") | Category ids and names |
| `browse_category` | List one category nearest-first, optionally filtered by OpenStreetMap tags | Places, nearest first |
| `get_place` | Full details for one place id | Hours, busiest hours, amenities, website, and ratings (out of 5) and reviews with their source. Foursquare and Google data needs premium data access |
| `locate` | Resolve an address, neighbourhood, city or landmark | Up to 3 matches with coordinates |
| `places_within_reach` | Places within a travel time by walking, cycling, driving or transit from `from` | Places inside the reachable area |
| `search_along_route` | Places along the route between two points, optionally through `stops`, by `category_ids` or `query` | Places with distance along the route and the minutes each stop adds |
| `plan_trip` | A door-to-door trip as Directions plans it, optionally through `stops` with time spent at each, a `kind` of travel and a time | When to leave and arrive, and each move: walks, rides, bike share stations, transit lines |
| `transit_trips` | Transit trips from `from` to `to`, departing at `depart_at` or arriving by `arrive_by` | When to leave and arrive, each line, direction and stop, and live delays |
| `transit_departures` | Live departure board at a named station or near a point | Next runs per line with minutes away, delays, cancellations and service alerts |
| `travel_times` | Door-to-door time by walking, cycling, driving and transit, to compare them. Needs premium navigation | Minutes per mode, or null where there is no route |
| `bikeshare_nearby` | Bike share stations around `near` | Live counts of bikes, e-bikes and free docks, nearest first |
| `weather` | Conditions at `at` | Temperature, wind, air quality, and whether rain is due in the next few hours |
| `saved_places` | Your saved places outside private collections, filtered by `query` | Names, addresses and coordinates |
| `my_vehicles` | Your cars, bikes and scooters | Where each was last parked |
| `create_canvas` | Save a canvas to your library from place ids other tools returned, one layer per `layers` entry. Needs library access (Basic or Premium) | The new canvas's name and layer count |

The in-app Ask can also search the web. MCP has no `web_search` tool, since your client can search the web itself.

Each result is JSON in a text block. Place lists include each place's id, name, type, address, coordinates, distance, opening hours and whether it is open now. Pass an id to `get_place` for the rest.

There is no map here, so a tool needs a point. Pass coordinates, a place id another tool returned, or a place name, which is looked up near you. A search without either fails with `isError: true` and a message telling the model to do that, which most models act on by themselves.

Times are written and read in the trip's own time zone: give `depart_at` as local time, like `2026-11-20T18:30`, and results come back as `Fri 18:42`.

Searches run as your account, in the language your client sends in `Accept-Language`. The assistant sees only what the tools return. Saved places in private collections, saved routes, friends' locations and location history are end-to-end encrypted, so the server cannot hand them over.
